# 论文 PDF 与网页收尾流程

原项目已有 PDF 导出逻辑。网页和 Agent Bridge 现在也覆盖完整的 26 个阶段：S22 修订之后，继续 S23 质量检查、S24 知识归档、S25 导出论文、S26 核查引用。

阶段顺序保持不变。最后的 `deliverables/` 打包会优先使用 S26 的引用核查后版本，再生成 PDF。是否通过质量检查、引用核查应以各自报告为准；生成 PDF 只代表完成排版。

编译器优先使用 PATH 中的 `pdflatex`，否则使用 PATH 中的 Tectonic，或项目目录下的 `.runtime/tectonic`。Tectonic 首次编译需要联网下载所需的 TeX 文件，后续可使用缓存。PDF 编译失败时仍保留 Markdown、LaTeX 等文件，并在 `deliverables/compile_report.json` 中说明原因。

网页的论文仓库显示 PDF 下载入口和 PDF 生成报告。原来停在 S22 的项目现在会显示还有收尾步骤；部署更新本身不会自动恢复任务或重新训练。用户主动恢复时会从 S23 继续。

S23 将完整修订稿交给质量评审，不再只取前 4 万个字符；报告中记录正文读取范围，避免把未读取的尾部章节误判为缺失。收尾阶段保留 S22 修订稿，不再通过模型重新改写正文或根据数值匹配结果删除数字。质量未达门槛时，保留原稿并注明“待修改稿”；质量报告和降级原因随最终产物一起打包。

导出和引用核查不再静默删除引用，不按相关性分数自动删文献。导出时会从此前的论文源码包补回已有的引用条目，不编造缺失条目。找不到、未核实及相关性有疑问的条目列入报告，原文与引用关系保留。`verification_report.json` 的 `fully_verified` 和 `verified_fraction` 表示核验覆盖情况；没有参考文献或存在缺失引用时不能宣称全部核验通过。

`manifest.json` 明确将产物标为待复核草稿，并记录质量与引用状态。`citation_coverage.json` 列出 LaTeX 中缺少对应文献条目的引用；编译成功仅表示排版成功。

2026-10-15 的现有任务已执行完 S26，但 S23 得分 2.5 低于 3.0 门槛。此前有缺陷的导出生成了 16 页版本，移除了 32 个引用标记，核查只覆盖剩余 1 条文献。因此 E 盘筛选包保留 15 页 S22 阅读版并附检查报告。代码修复不会自动重跑任务，也不代表实验协议与来源追溯问题已解决。
