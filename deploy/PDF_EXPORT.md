# 论文 PDF 与网页收尾流程

原项目已有 PDF 导出逻辑。网页和 Agent Bridge 现在也覆盖完整的 26 个阶段：S22 修订之后，继续 S23 质量检查、S24 知识归档、S25 导出论文、S26 核查引用。

阶段顺序保持不变。最后的 `deliverables/` 打包会优先使用 S26 的引用核查后版本，再生成 PDF。是否通过质量检查、引用核查应以各自报告为准；生成 PDF 只代表完成排版。

编译器优先使用 PATH 中的 `pdflatex`，否则使用 PATH 中的 Tectonic，或项目目录下的 `.runtime/tectonic`。Tectonic 首次编译需要联网下载所需的 TeX 文件，后续可使用缓存。PDF 编译失败时仍保留 Markdown、LaTeX 等文件，并在 `deliverables/compile_report.json` 中说明原因。

网页的论文仓库显示 PDF 下载入口和 PDF 生成报告。原来停在 S22 的项目现在会显示还有收尾步骤；部署更新本身不会自动恢复任务或重新训练。用户主动恢复时会从 S23 继续。

2026-10-15 已有产物的 PDF 为 S22 修订稿排版版，共 15 页，并未补跑 S23–S26，也不代表评审指出的实验协议、来源追溯问题已解决。
